## Dependency notes

- Plan 001 is the prerequisite because a clean checkout currently cannot install dependencies or
  execute any other plan's verification gates.
- Plans 002 and 003 modify disjoint production paths and can be assigned independently after Plan
  001. Plan 005 follows Plan 003 because both change replay discovery copy and the fallback branch
  changes `src/core/tools/replay.ts`.
- Plan 003 has a hard asset-readiness fork. If Steel has an immutable CORS-enabled asset URL, it
  externalizes Hls.js and keeps the app. If not, it ships dashboard-only replay: Plan 004's
  replay-runtime slice waits for the asset, while its RC browser-gate slice still proceeds.
- Plan 004 depends on Plan 003's preferred external-asset outcome because it changes the same replay
  state machine and browser harness. Its CI/browser-gate slice still runs after a dashboard-only
  outcome; only polling/media work is blocked in that case.
- Plan 005's contract/copy slice is required for rc.1; its real mobile E2E extension is post-RC.
- Plan 006 is the release runbook. Run its clean-checkout gate after all required slices:
  typecheck, lint, unit, integration, budget, conformance, browser, E2E, MCPB, Docker, and Desktop
  smoke.

## Findings already addressed in the live worktree

- Replay manifests are now restricted to the exact `fly.storage.tigris.dev` origin declared by the
  app CSP. Plan 004 preserves this improvement by removing the duplicated origin literal and adding
  an invariant test; it does not reopen the origin policy.
- Replay recovery now waits for complete `ui/notifications/tool-input` and refuses a mismatched
  pushed result. Plan 003 builds on that state machine rather than replacing it.
- Fatal HLS failures now make at most two UUID-pinned refresh attempts. Plan 004 keeps this separate
  from recording-finalization polling.
- The implemented dirty-tree candidate passes 866 unit/integration tests, 48 browser tests in three
  consecutive runs, 17 E2E tests, typecheck, lint, build, budgets, conformance, MCPB inspection, and
  both container entrypoint smokes. Plan 006 still requires the normal reviewed merge, Actions
  build, Claude Desktop smoke of those exact Actions bytes, and protected publish approval.

## Blocked follow-ups found during execution

- The external-asset replay runtime in Plan 004 remains blocked because no immutable Steel-owned,
  CORS-enabled Hls.js asset URL and SRI contract was supplied. rc.1 therefore uses Plan 003's safe
  dashboard-only fallback and contains no replay app or Hls.js bytes.
- Plan 005's real mobile probe reached self-hosted Steel successfully and observed a mobile user
  agent, but `navigator.maxTouchPoints` remained `0`. The test was not weakened or shipped failing;
  complete that coverage after self-hosted `deviceConfig.mobile` enables touch emulation.

## Findings considered and deferred

- **Changing partial diagnostics success into failure:** one diagnostics endpoint can fail while the
  other succeeds. The current code intentionally returns the surviving timeline with a note. Do not
  change this until the Steel REST layer exposes a stable error taxonomy that distinguishes an
  unsupported endpoint from cancellation, authorization, and transient failures.
- **Supporting arbitrary replay media origins:** not worth widening now. The measured Steel Cloud
  contract and current CSP both use the exact Tigris origin. If Steel changes storage providers,
  update the single shared origin constant and its contract probe together.
- **Recording live-viewer takeover interactions:** direct viewer input travels over CDP and is not
  guaranteed to reach Steel's agent-trace endpoint. Plan 005 corrects the product promise now. Add
  instrumentation only if a product requirement demands a complete human-interaction audit trail;
  that follow-up needs a privacy/security design for clicks, scrolls, and redacted typing metadata,
  not a quick logging patch.
- **Changing Steel artifact disposition:** explicitly rejected for this release. The endpoint remains
  `Content-Disposition: attachment`; the MCP server owns bounded inline image blocks and preserves the
  URL as a download fallback.
